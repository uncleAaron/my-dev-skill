# 开发实现

按 tasks.json 依赖选择就绪任务。开启任务尝试后读取对应 AC、详细设计段落和文件，先建立有意义的失败测试。缺陷修复先复现；检查失败来自目标行为而非测试环境错误。

实现最小满足契约的代码；运行针对性验证，重构后再验证。保留已有断言，沿用项目格式化、静态检查与测试约定。纯文档变更用结构与内容检查，无需编造单元测试。

失败时阅读完整错误，定位输入与根因，提出一个解释，最小修改验证它。修复前结束旧尝试并预扣下一尝试，不进行无界试错。代码变化后重新获取当前指纹的证据。

任务完成要求所有声明验证有本次尝试的当前通过证据。多任务顺序开发时，后续代码会使先前证据失效；整体验收须重新打开受影响任务并重跑。回归耗用同一修复预算，预算不足时报告用户，不暗中扩充。

提交只包含当前任务文件，先审查 git diff，遵循项目现有授权。用户未提交改动不擅自暂存、回滚或提交。
