# 恢复与需求变化

先 status，再 resume。核对 Git HEAD、用户未提交变化、当前需求、任务及真实文件，不凭旧 done 状态认定完成。resume 不开始新用户调用，不重置预算；只有新的明确用户请求才能 begin-call。

running 的遗留尝试变为 interrupted；任务回到待核对，下一次执行使用 --repair；中断不返还预算。新代码或测试变化使旧证据失效，重新执行。规格业务变化执行 revise --reason，revision 增加并返回 specify，重做影响分析、设计、任务和验证。

根锁存在时先检查主机与 PID。确认本机 owner 已退出才用 unlock；其他主机或无法判断时报告阻塞。状态损坏时保留原文件，不用新建状态掩盖。状态丢失但已有文档时先备份，再在用户确认的恢复范围内重建到最早未验证阶段。

日志和证据默认在 .workflow，不自动推送。跨机器无证据时重新验证，不能用报告摘要伪造历史执行。重置修复预算仅在用户明确允许后调用 reset-repairs，并写授权依据。
