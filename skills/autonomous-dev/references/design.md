# 详细设计

阅读特性、相关代码、构建配置与现有测试；沿用项目技术栈。

填写 design.md：模块职责、接口请求/响应/错误、字段和约束、事务与一致性、幂等、权限、异常、超时重试、可观测性、兼容、迁移与回退。每项引用 AC 编号。未涉及的内容写“不适用：具体理由”。

为变更提供可检查契约：函数/接口签名、业务不变量、数据唯一键与边界、上下游失败行为。复杂交互可用小型 Mermaid 图，但图不能替代字段契约。

明确测试层级、依赖、数据和环境成本。将尚未验证的架构假设记录在设计中，先做最小验证再大范围实现。

完成条件：实施者可据此开发；无未解决的关键业务决定；设计与现有系统兼容性、AC 和测试策略对应。
