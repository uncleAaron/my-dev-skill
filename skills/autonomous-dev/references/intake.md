# 接收需求

记录用户原始请求、上下文、范围和预期结果；读取仓库约定、相关业务代码、构建和测试入口。先通过 git status 检查用户改动，避免覆盖。基线失败与本次引入失败分开记录。

填写 intake.md 的来源、范围、环境、基线、假设、关键问题。环境记录 Python/Git/OpenCode 具体版本、系统、业务依赖和测试入口；模型名未知时如实记录。企业网标签如有使用：bs=业务网，gw=办公网，实际访问限制以当前项目为准。

新项目仍需先处于 Git 仓库；该 Skill 不代替用户选择业务技术栈。已有项目沿用当前栈，普通实现细节自行决定并解释原因。

完成条件：需求来源可追溯、边界明确、代码和测试入口已侦察；关键问题有解决结论或持久化阻塞。
