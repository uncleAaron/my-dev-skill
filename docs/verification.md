## Agent 使用验证

独立场景在全新临时业务仓库中要求 Agent 按本 Skill 实现运费规则，实际使用 CLI 并形成产物。该场景与 examples/demo.py 分离；已完成：独立 Agent 在运费规则场景中实际运行 CLI，留下红测后修复记录，5 项 unittest 通过，前后指纹一致，最终 check 无错误、状态 complete；控制脚本与 OpenCode 宿主分开验证。没有 OpenCode 宿主，故只验证另一 Agent 能否遵循工作流，不能证明 OpenCode 或内部模型兼容。

无 Skill 的压力场景对照也能正确拒绝零测试和旧 done 结论，因此不能声称该 Skill 相比基线提升了模型的安全性或正确率。

## 已知边界

- 单 Agent 语义自审不等于独立评审；结构门禁无法证明业务要求理解正确。
- 状态与审查文件可由有文件写权限的 Agent 修改，这是协作协议，不是防恶意篡改系统。
- 调用标识按新用户请求创建，CLI 无法验证请求真实性；不能作为资源计费安全边界。
- 原始日志只做常见模式脱敏，外发前仍需检查敏感内容。
- 首版保守使变化后的验证失效；回归重跑消耗修复预算，较大需求需合理拆分及用户显式追加预算。
- 控制脚本无第三方依赖；业务依赖、JDK/数据库/下游环境仍由具体项目提供。
- 进程退出后不会自动唤醒，跨主机状态/证据丢失需要重建或重跑。
- 尚无 Windows、OpenCode v2.0.26 或内部 DeepSeek 实机结果。

## 实现取舍

- 采用 Python 3.10+ 标准库；业务项目依赖和内部模型仍沿用项目现有配置。
- 增加 acceptance.json，将 AC 对真实/Mock 的要求变成可检查映射；增加显式阻塞解除及知识合并命令。
- 调用与任务尝试独立持久化，run 必须绑定 attempt_id；资源预算属于协作约定。
- 命令在显式 `--` 后接参数，避免解析器吞掉 --attempt 等选项。
- 离线样例用 Python -B 避免同秒修改同大小源码时读取陈旧字节码；知识与渲染报告不进入业务源码指纹。
- Skill 是供业务仓库安装的产物，不会安装到 ChatGPT 个人技能目录。
