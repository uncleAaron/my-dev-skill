# F001：OpenCode 自驱动开发工作流特性文档

日期：2026-10-27；状态：待审阅的设计基线。

## 一、需求来源与目标

用户要求从需求接收走完开发、测试验证、知识沉淀、测试案例沉淀、文档沉淀的 SDD 全链路，并明确要求产出特性文档、详细设计及任务拆分，以 OpenCode 为首要平台。

用户认可的实现范围：主控 Skill＋阶段能力＋执行脚本＋持久化状态；第一版在运行中的会话自动推进，中断后可恢复。

SDD 在此指 Specification-Driven Development。规格约束实现与验收；实现变更必须回写受影响的规格，保留修订原因与验证记录。

## 二、环境与设计取舍

- 首要部署环境：Windows、公司纯内网、OpenCode、内部 DeepSeek。用户此前版本为 v2.0.26，尚未在该具体版本实机验证。
- 设计采用 Python 3.10+ 标准库、Git 和 Markdown/JSON；这是实施方提出的默认值，Python 是需预置的额外依赖。
- 业务仓库可以使用 Java、JavaScript、Python 等；构建工具及依赖沿用业务项目。
- 采用项目级目录安装，避免覆盖全局配置；不依赖符号链接、Bash 或联网安装。
- 第一版支持单个工作流写入一个业务工作区；多特性可排队，不支持并发修改同一工作区。
- 不将多 Agent 作为必要条件。按同一检查清单进行单会话自审，并如实标注其独立性限制。

## 三、典型用户故事

1. 开发者交付新需求，Agent 读取代码与已有资料，生成特性、设计、计划，自动实施到可验收状态。
2. 开发者报告缺陷，Agent 先建立复现与回归场景，再修复并更新受影响文档。
3. 上次任务被中断，新会话读取状态并核对工作区，恢复未完成任务。
4. 下游不可访问，Agent 完成可验证部分，区分 Mock 与真实验证，记录整体验收阻塞。
5. 需求中途变化，Agent 修订规格，找出受影响的任务和测试，使旧验证失效并重新执行。

## 四、功能与验收标准

| 编号 | 要求 | 验收条件 |
|---|---|---|
| AC-01 | 需求接收与项目侦察 | 记录需求来源、范围、仓库约定、环境检查、既有失败、假设和关键待决问题；检查用户未提交改动 |
| AC-02 | 特性文档 | 每个验收条件有稳定编号；覆盖正常、异常、边界、非功能要求；明确范围外内容 |
| AC-03 | 详细设计 | 对相关模块、接口、数据、事务、幂等、异常、权限、兼容、迁移、观测给出决定；不适用项附理由 |
| AC-04 | 任务拆分 | 每个任务有稳定编号、依赖、关联 AC、设计段落、修改范围、输入输出、验证命令和完成条件；依赖无环 |
| AC-05 | 自驱动推进 | 无关键阻塞时依序完成阶段；普通技术取舍自行记录；不在每个阶段重复索取确认 |
| AC-06 | 开发与修复 | 任务可验证后标记完成；缺陷修复提供失败复现和回归证据；不删除断言来制造成功 |
| AC-07 | 验证可信 | 每次执行记录参数、目录、时间、退出码、代码与规格指纹、日志和验证类型；跳过、超时、错误、Mock 不冒充真实通过 |
| AC-08 | 测试沉淀 | 持久化回归测试、场景索引、数据准备、隔离、清理和下游策略；用例关联 AC 与执行证据 |
| AC-09 | 文档同步 | 交付前核对规格、设计、任务、代码、测试与使用说明；未完成与未验证项显式列出 |
| AC-10 | 知识沉淀 | 每项经验有触发条件、结论、适用范围、证据、复核条件；主题索引按需检索，冲突条目可替代或过期 |
| AC-11 | 中断恢复 | 原子写入状态；恢复时核对工作区、内容指纹与未完成执行；拒绝直接信任陈旧 done 状态 |
| AC-12 | 有界执行 | 单任务自动修复默认最多 3 次；单次调用最多 30 个任务执行尝试；重启会话不自动重置修复预算 |
| AC-13 | 内网可用 | Skill 和控制脚本离线运行；依赖缺失给出具体阻塞；不自动下载依赖或改模型配置 |
| AC-14 | 受控交付 | 自动完成本地代码与资料；提交/推送按项目显式授权执行，合并、生产发布及生产数据变更需已有明确授权 |

## 五、问题处理与完成定义

低风险、可逆且不改变业务语义的歧义记录假设后继续；影响业务规则、接口兼容、数据归属或不可逆操作的问题必须记录并询问。等待期间可以继续无依赖任务。

某项必需验收缺少环境或证据时，整体结果是 blocked，不是 complete。可输出部分交付报告，标明已完成范围、缺口、解除条件和恢复命令。

业务验收不要求人为设置覆盖率数字；使用项目已有标准。新能力、缺陷和风险分支必须具备有意义的验证，纯说明文档变更使用链接、结构与内容审查即可。

## 六、范围外与后续演进

第一版不包含进程退出后自动唤醒、外部调度器、多仓库分布式事务、无人监督生产发布、知识向量数据库和强制多 Agent。后续可增加外部执行器、团队知识检索及多仓库编排，保留当前产物契约。

## 七、本工作流自身的验收证据

实现阶段需运行脚本测试和三组隔离样例：新功能闭环、缺陷修复闭环、中断恢复/规格变更闭环；额外在 Windows OpenCode 上完成 Skill 发现、调用和恢复冒烟。当前仅完成设计，无这些运行证据。
